# Пользовательские сценарии

Актор во всех сценариях — **кандидат**, который готовится к собеседованию в Telegram-боте. Системные участники: Telegram-бот (handlers и FSM), сервисы приложения, OpenAI API, SQLite (`data/app.db`) и CSV-база знаний (`knowledge_base/`).

Во всех сценариях при ошибке пользователь видит короткое нейтральное сообщение без технических деталей, API key, stack trace и содержимого запроса.

## UC-01. Запуск бота

- **Actor:** кандидат.
- **Preconditions:** бот запущен (`python -m app.main`), в `.env` задан `BOT_TOKEN`.
- **Main Flow:**
  1. Кандидат отправляет `/start`.
  2. `UserService` находит или создаёт пользователя по Telegram ID.
  3. FSM переходит в `MAIN_MENU`.
  4. Бот показывает приветствие и главное меню: «🎯 Подготовка по вакансии», «📋 Чек-листы», «ℹ️ Помощь».
- **Alternative Flows:**
  - A1. Кандидат нажимает «ℹ️ Помощь»: бот показывает справку и кнопку «🏠 Главное меню».
  - A2. Ошибка базы данных: бот сообщает «Не удалось сохранить данные. Попробуйте ещё раз.», меню не показывается; кандидат повторяет `/start`.
  - A3. `/start` в середине сценария сбрасывает FSM и открывает главное меню; сохранённые данные не удаляются.
- **Result:** пользователь зарегистрирован, открыто главное меню.

## UC-02. Ввод вакансии

- **Actor:** кандидат.
- **Preconditions:** открыто главное меню (UC-01).
- **Main Flow:**
  1. Кандидат нажимает «🎯 Подготовка по вакансии»; FSM → `WAITING_VACANCY`.
  2. Бот просит прислать полный текст вакансии.
  3. Кандидат отправляет текст одним сообщением.
  4. `vacancy_validator` проверяет: текст не пустой, не короче 100 символов.
  5. `VacancyService` сохраняет вакансию, `InterviewSessionService` создаёт сессию подготовки.
  6. Запускается UC-03.
- **Alternative Flows:**
  - A1. Прислан файл, фото или стикер: бот просит отправить текст; FSM остаётся `WAITING_VACANCY`.
  - A2. Текст короче 100 символов: бот просит прислать более подробный текст.
  - A3. Ошибка базы данных: «Не удалось сохранить данные. Попробуйте ещё раз.»
- **Result:** вакансия и сессия сохранены в БД.

## UC-03. Анализ вакансии

- **Actor:** кандидат (система выполняет анализ).
- **Preconditions:** вакансия сохранена (UC-02).
- **Main Flow:**
  1. FSM → `ANALYZING_VACANCY`, бот сообщает «Анализирую…».
  2. `VacancyService.analyze()` вызывает `OpenAIService.analyze_vacancy()` с промптом `vacancy_analysis.txt`.
  3. Результат `VacancyAnalysis` сохраняется в `vacancies.analysis_json`.
  4. FSM → `VACANCY_RESULT`; бот показывает позицию, компанию, навыки, опыт, обязанности и темы, а также кнопку «🎯 Сформировать вопросы».
- **Alternative Flows:**
  - A1. Кандидат пишет во время анализа: «Анализ ещё выполняется, подождите».
  - A2. Ошибка OpenAI (таймаут, ключ, отказ, невалидный ответ): «Не удалось проанализировать вакансию…»; FSM → `WAITING_VACANCY`, можно прислать текст снова.
  - A3. Ошибка БД: сообщение об ошибке сохранения, FSM → `WAITING_VACANCY`.
- **Result:** анализ вакансии сохранён и показан.

## UC-04. Генерация вопросов

- **Actor:** кандидат.
- **Preconditions:** есть сохранённый анализ вакансии (UC-03).
- **Main Flow:**
  1. Кандидат нажимает «🎯 Сформировать вопросы»; FSM → `GENERATING_QUESTIONS`.
  2. `QuestionService` берёт анализ вакансии и через `KnowledgeService.find_relevant()` подбирает до 20 вопросов из `questions.csv` (профессия по названию позиции и `professions.csv`, категории, ключевые слова навыков и тем).
  3. `OpenAIService.generate_questions()` (промпт `questions.txt`) возвращает до 10 вопросов.
  4. Вопросы сохраняются в `interview_questions`; FSM → `QUESTIONS`.
  5. Бот показывает список вопросов кнопками, а также «📊 Итоги подготовки» и «🏠 Главное меню».
- **Alternative Flows:**
  - A1. Вопросы для сессии уже есть: показываются сохранённые, OpenAI не вызывается.
  - A2. В базе знаний нет подходящих материалов или CSV недоступен: вопросы строятся только по анализу вакансии.
  - A3. Ошибка OpenAI: «Не удалось сформировать вопросы…»; можно повторить.
  - A4. Нет анализа вакансии: «Начните заново из главного меню».
- **Result:** сессия содержит набор вопросов.

## UC-05. Ответ на вопрос

- **Actor:** кандидат.
- **Preconditions:** вопросы сформированы (UC-04).
- **Main Flow:**
  1. Кандидат выбирает вопрос; FSM → `WAITING_ANSWER`.
  2. Бот показывает вопрос, категорию и, если нужно, подсказку отвечать по STAR.
  3. Кандидат отправляет ответ текстом.
  4. `answer_validator` проверяет ответ: не пустой, не тривиальный («да», «не знаю»), не короче 10 символов.
  5. Запускается UC-06.
- **Alternative Flows:**
  - A1. На вопрос уже есть сохранённый ответ: бот показывает последний разбор (FSM → `NEXT_ACTION`) и кнопку «🔁 Ответить заново».
  - A2. Голосовое, файл или стикер: бот просит ответить текстом, OpenAI не вызывается.
  - A3. Слишком короткий ответ: бот просит ответить развёрнуто, OpenAI не вызывается.
- **Result:** ответ принят к анализу.

## UC-06. Анализ ответа

- **Actor:** кандидат (система выполняет анализ).
- **Preconditions:** ответ прошёл проверку (UC-05).
- **Main Flow:**
  1. FSM → `ANALYZING_ANSWER`, бот сообщает «Анализирую ваш ответ…».
  2. Если вопрос требует STAR, `AnswerService` подбирает до 2 примеров из `star_examples.csv` через `KnowledgeService.find_star_examples()`.
  3. `OpenAIService.analyze_answer()` (промпт `answer_analysis.txt`) получает анализ вакансии, вопрос, ответ и, если есть, `<star_examples>`.
  4. В одной транзакции сохраняются ответ, разбор и статус сессии.
  5. FSM → `ANSWER_RESULT` → `NEXT_ACTION`; бот показывает оценку, разбор STAR, сильные и слабые стороны, рекомендации, улучшенный ответ.
  6. Кнопки: «➡️ Следующий вопрос», «🔁 Ответить заново», «📋 К списку вопросов», «📊 Итоги подготовки», «🏠 Главное меню».
- **Alternative Flows:**
  - A1. Ошибка OpenAI: «Не удалось проанализировать ответ…»; ответ не сохраняется, FSM → `WAITING_ANSWER`.
  - A2. Ошибка БД: rollback, сообщение об ошибке сохранения.
  - A3. Файл STAR-примеров недоступен или примеров нет: анализ идёт без блока `<star_examples>`.
  - A4. «➡️ Следующий вопрос» после последнего вопроса: бот показывает список вопросов.
- **Result:** разбор ответа сохранён и показан.

## UC-07. Повторный ответ

- **Actor:** кандидат.
- **Preconditions:** на вопрос есть сохранённый разбор (UC-06).
- **Main Flow:**
  1. Кандидат нажимает «🔁 Ответить заново»; FSM → `WAITING_ANSWER`.
  2. Кандидат отправляет новый ответ; выполняются шаги UC-05 и UC-06.
  3. Сохраняется новая запись ответа; при повторном открытии вопроса показывается последний разбор.
  4. Сохранённый итог сессии сбрасывается, чтобы он соответствовал новым ответам.
- **Alternative Flows:** как в UC-05 и UC-06; при ошибке OpenAI предыдущий разбор остаётся актуальным.
- **Result:** у вопроса новый актуальный разбор.

## UC-08. Итоговый отчёт

- **Actor:** кандидат.
- **Preconditions:** в сессии есть хотя бы один проанализированный ответ.
- **Main Flow:**
  1. Кандидат нажимает «📊 Итоги подготовки»; FSM → `GENERATING_SUMMARY`.
  2. `SessionSummaryService` берёт последние разборы по каждому вопросу и считает статистику в Python: количество ответов, средний балл, статистику STAR.
  3. `OpenAIService.summarize_session()` (промпт `session_summary.txt`) формирует содержательную часть; числовые значения берутся из Python.
  4. Итог сохраняется в `interview_sessions.summary_json`; FSM → `SUMMARY_RESULT`.
  5. Бот показывает отчёт: статистику, сильные и слабые стороны, STAR, рекомендации, темы для повторения, общий вывод.
- **Alternative Flows:**
  - A1. Нет ни одного ответа: «Сначала ответьте хотя бы на один вопрос», OpenAI не вызывается.
  - A2. Итог уже сохранён и ответы не менялись: показывается сохранённый итог без вызова OpenAI.
  - A3. Ошибка OpenAI: «Не удалось сформировать итоговый отчёт. Ваши ответы сохранены.», кнопка «🔄 Повторить»; FSM возвращается в предыдущее состояние.
- **Result:** итоговый отчёт сохранён и показан.

## UC-09. Чек-листы

- **Actor:** кандидат.
- **Preconditions:** открыто главное меню. Вакансия и сессия не нужны.
- **Main Flow:**
  1. Кандидат нажимает «📋 Чек-листы» (`menu:checklists`).
  2. `ChecklistService.list_categories()` читает `checklists.csv`; бот показывает категории: «📝 До интервью», «🎒 Что взять с собой», «👔 Внешний вид», «✅ Проверка перед началом», «💬 Во время интервью», «🤝 Завершение интервью», «📬 После интервью».
  3. Кандидат выбирает категорию (`checklist:{category}`).
  4. Бот показывает общие пункты (❗ — обязательные), затем блок «🎯 Дополнительно для отдельных профессий» с названием профессии.
  5. Кнопки «⬅️ К чек-листам» и «🏠 Главное меню».
- **Alternative Flows:**
  - A1. Файл чек-листов отсутствует или пуст: «Чек-листы пока недоступны», кнопка главного меню.
  - A2. В категории нет пунктов: «В этом разделе пока нет пунктов.»
  - A3. Просмотр чек-листов не меняет состояние FSM. Кнопка «🏠 Главное меню» переводит FSM в `MAIN_MENU`, как и в остальных сценариях; сохранённые вакансии, вопросы и ответы не затрагиваются.
- **Result:** кандидат видит чек-лист. Прогресс не сохраняется, OpenAI не вызывается.
